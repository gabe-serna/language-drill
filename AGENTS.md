# Agent guidance

- Consult the [README](README.md) for setup and commands, the [architecture](docs/ARCHITECTURE.md) for the component being changed, and the [roadmap](docs/ROADMAP.md) for milestone scope. Get explicit approval before starting a later milestone. Read archived documents only when a task specifically needs historical context.
- Update the relevant documentation when behavior changes. Replace obsolete information in place and keep each fact in its most useful document. Keep historical benchmark results and troubleshooting logs out of active architecture documentation.
- Design every feature so its study behavior, rules, prompts, and state live in the TypeScript core and can run without Pi. Pi code should only adapt that functionality to Pi commands, UI, lifecycle, and model APIs. Pass external services through the core's provider contracts so another interface can use the same feature without rewriting it. Keep Python limited to Sudachi analysis. Resolve Windows paths from the project or module, use UTF-8, pass subprocess arguments directly, and handle timeout and cleanup.
- Keep Pi integrations project-local under `.pi/`. Resolve the model from Pi for every inference request and use fresh isolated contexts. Keep model and provider settings in Pi.
- Keep Anki read-only and study state in memory. Validate external data, enforce vocabulary and eligibility rules deterministically across retries, and require explicit user authorization for foundational vocabulary edits.
- Use synthetic test fixtures. Keep credentials, personal deck contents, learner answers, and raw debug traces out of version control.
